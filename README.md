# Nuclear Medicine Atlas

A single-file, offline-capable, evidence-graded nuclear medicine reference — **272 pages
across 25 chapters**, interactive calculators, a study / mock-exam engine with spaced
repetition, guided learning paths, light/dark themes, and CrossRef-verified primary-source
citations. The entire site compiles to one self-contained **`index.html`** (all CSS and JS
inlined), so it works from any static host and even offline.

> **Educational resource — not medical advice.** See the in-app *Disclaimer & Terms of Use*.
> Review-status badges are placeholders pending independent physician review before public launch.

## Deploy to GitHub Pages

You have two options. **Option A is the simplest and needs no build tools.**

### Option A — serve the prebuilt file (recommended to start)
1. Create a new GitHub repository and push everything in this folder to the `main` branch.
2. In the repo, go to **Settings → Pages**.
3. Under **Source**, choose **Deploy from a branch**, select **`main`** and **`/ (root)`**, then **Save**.
4. Wait ~1 minute. Your atlas is live at `https://<username>.github.io/<repo>/`.

`index.html` is at the repo root, and an empty `.nojekyll` file is included so GitHub serves the
files as-is (no Jekyll processing). Nothing else is required.

### Option B — auto-rebuild from source on every push
If you want the site to rebuild automatically whenever you edit the Markdown content:
1. Push this folder to `main`.
2. **Settings → Pages → Source → GitHub Actions.**
3. The included workflow (`.github/workflows/deploy.yml`) installs Python, runs `build_site.py`
   and `validate.py`, and publishes the result. Edit content → commit → the live site updates.

### Custom domain (optional)
Point your domain's DNS at GitHub Pages, then add a file named `CNAME` at the repo root
containing just your domain (e.g. `atlas.example.com`), and set the same domain under
**Settings → Pages → Custom domain**. Do **not** add a `CNAME` file unless you own the domain —
it overrides the default `github.io` address.

## Set your canonical URL

For correct `<link rel="canonical">`, Open Graph tags, and `sitemap.xml`, set your real address
once in **`build_site.py`**:

```python
SITE_URL = "https://your-domain-or-username.github.io/your-repo"
```

Then rebuild (`python build_site.py`). If you use Option A, commit the regenerated `index.html`,
`sitemap.xml`, and `robots.txt`.

## Build from source locally

```bash
pip install markdown pyyaml      # only two dependencies
python build_site.py             # writes index.html + robots.txt + sitemap.xml
python validate.py               # hard invariants + health report (run after every build)
```

> Note: `build_site.py` writes `nuclear-medicine-atlas.html`; for Pages, that file is also copied
> to `index.html`. The Actions workflow does this copy automatically; when building locally for
> Option A, copy it yourself: `cp nuclear-medicine-atlas.html index.html`.

## Repository layout

```

nuclear-medicine-atlas.html    identical build output (source-of-record name)
build_site.py                  generator: content/ + assets/ → the single HTML file
validate.py                    QA harness: navigation, citations, JS syntax, health report
content/                       every page as Markdown + front-matter (the source of truth)
assets/                        atlas.css, atlas.js, assets/tools/*.html (the calculators)
docs/                          launch, peer-review, and image-sourcing guides
robots.txt, sitemap.xml        deployment/SEO artifacts (regenerated by the build)
404.html                       redirects stray paths back into the single-page app
.nojekyll                      tells GitHub Pages to skip Jekyll processing
.github/workflows/deploy.yml   optional auto-build-and-deploy (Option B)
CHANGELOG.md                   versioned release history
LICENSE.md                     license (edit the placeholder owner name before publishing)
```

## Before you go fully public

Three things elevate this from a strong draft to a citable authority — see `docs/` for guides:
- **Independent physician review** of the clinical pages (flip the review-status badges to truthful).
- **Real, permissioned images** (it's an *atlas*; the figure slots are ready for them).
- **Set `SITE_URL`** and fill in the license owner and contact email (`CONTACT_EMAIL` in `build_site.py`).
